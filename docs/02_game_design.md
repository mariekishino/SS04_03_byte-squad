# ゲーム仕様

## 世界観と最初に伝えること

プレイヤーは宇宙船の通信士。観測データを通信予算内に収め、地球で元どおりに復元することが任務。最初の画面では「何をしたいのか」「何が障害か」「何を操作するか」「どうなれば成功か」を操作開始前に伝える。

### 開始画面の文章

> ### 宇宙の発見を、地球へ届けよう。
>
> あなたは宇宙船の通信士。
> 集めた観測データを地球へ送りたいけれど、そのままでは通信容量の上限を超えてしまいます。
>
> データの並びから規則を見つけて、小さくまとめましょう。
> ただし、情報を失ってはいけません。
>
> **容量以内に収めて送り、地球で元どおりに戻せたらミッションクリア！**

この説明は最初の圧縮任務の動機を伝えるもの。すべての任務で無圧縮が上限を超えるわけではなく、ゲーム任務2では圧縮しない判断も学ぶ。

補足は「今回は文字データの圧縮・復元の基礎を体験します。実ファイルの保存やZIPの展開は、今後の学習範囲です」。画面の操作名は「元に戻す（復元）」を基本にし、ZIPからファイルを取り出す「展開」と区別する。

### 入口とモード

| 入口 | 添える説明 | プレイヤーが行うこと |
| --- | --- | --- |
| チュートリアル：通信の練習 | ガイドと一緒に、圧縮と復元の仕組みを体験しよう。 | 自動処理の途中経過を進めたり戻したりして観察する |
| ゲーム：通信任務に挑戦 | 自分でデータをまとめ、限られた容量で地球へ届けよう。 | 個数・文字や方式を決め、送信して修正する |

どちらも開始画面から直接選べる。チュートリアル完了をゲームの解放条件にしない。自由実験は別の補助入口として配置し、上の2つの選択を埋もれさせない。未実装の入口は準備中と明記し、押せるように見せない。

## 基本ループ

- チュートリアル：説明 → 圧縮を観察 → 送信 → 復元を観察 → 練習完了。
- ゲーム：任務を見る → 個数と文字で組を作る／方式を選ぶ → 送信 → 地球の復元結果を見る → 編集して再送、または次の任務へ。
- 自由実験：元データを入力 → 方式を比較 → 圧縮・復元を観察。

ゲームの中心は「予想する・作る・結果を見る・直す」。自動圧縮の再生を最後まで見ることを、ゲームでの送信の条件にしない。受信側は実際の復元処理を表示し、自動再生・停止・前後のステップを使える。「結果を見る」で検証済みトレースの末尾へ進むこともでき、再試行のたびに全ステップを手送りする必要はない。

「送信」はブラウザ内のシミュレーションであり、外部へのネットワーク通信はしない。時間制限・残機・試行回数の減点は設けない。

## チュートリアル：連続を数える（旧ミッション1）

- 現在のミッション1の処理とステップ操作を再利用する。RLE固定。
- 読み取り位置、現在の値・個数、確定した組を表示する。
- 「次へ」で1イベントずつ進み、最終出力は`(6,A) (4,B) (2,C)`。
- 圧縮完了後に送信可能。復元もステップ操作できる。
- 元12 B、本体6 B。復元完了後、一致と予算内を確認する。
- 常に「チュートリアル」と表示し、完了は「練習完了 / TRAINING COMPLETE」。ゲームのクリア件数には含めない。
- 完了後に「通信任務に挑戦」と「もう一度練習」の入口を置く。途中でもホームへ戻れる。

## ゲーム共通：自分で組を作る

ゲームで入力するのは圧縮後の「個数・文字」の組。課題の元データを編集する操作とは分ける。

- RLEでは「個数」「文字」のラベル付き入力欄と「組を追加」を置く。個数は1～255の整数、文字は半角A～Zの1文字。個数の＋／−、文字の選択でも操作できるようにする。
- 入力前に正しい個数や文字を自動で埋めない。初期の文字は未選択とし、入力に必要な説明を付ける。
- 入力値を検証してから本体バイトを作る。空欄・0・小数・256以上・複数文字・小文字等には理由を示す。型付き配列の丸め込みや暗黙の変換を行わない。
- **形式上合法でも、元データと合わない組は追加・送信できる。** 間違った文字、個数不足、過剰な個数も実際に復元し、結果で違いを示す。元データとの一致を入力時の禁止条件にしない。
- 組は追加した順に送信する。末尾の取消と各組の編集を用意し、失敗後も作業中の組を保持する。
- 確定した1組につき本体は2 B増える。個数入力中の未確定の組は容量に含めない。
- 1組以上の確定済みデータがあれば、元データ全体を表していなくても送信可能。編集中の未確定入力がある場合は、追加または取消を促して送信を無効にする。
- 予算超過でも「予算を超えて試す」として送信できる。復元上限4096 Bは通常どおり適用し、超過した場合は形式エラーとして理由を示す。
- 無圧縮では課題の元データをそのまま送る。RLEの手入力データを無圧縮データとして使わない。
- 答えは送信前に自動修正しない。手動の組を自動エンコーダーの正解へ置き換えない。

旧仕様の「未処理の先頭から同じ文字だけを選ぶ」「全入力を処理するまで送信不可」はゲームでは採用しない。間違いを作れない操作から、復元結果を見て修正できる操作へ変更するため。照準は観察の補助に使い、正解範囲への制限や文字の自動入力には使わない。

## ゲーム任務1：自分でまとめる（旧ミッション2）

- RLE固定。空の組一覧から始め、`AAAABBCCCC`を上限6 Bで送る。
- 最良結果は`(4,A) (2,B) (4,C)`で6 B。元10 B。
- A4個をA2個ずつに分けても復元は正しいが、本体8 Bになり予算を超える。編集して3組にまとめれば成功。
- `(3,A) (2,B) (4,C)`なら本体6 Bでも内容が不一致。誤った文字を入力した場合も受信側にその文字が現れる。
- 不足・余分・最初に違う位置を具体的に示し、入力欄へ戻って修正できる。
- 最初に独立したゲームとして完成させ、正解を作る・失敗する・直して成功する流れを確認する。

## ゲーム任務2：圧縮の逆効果（旧ミッション3）

- RLEと無圧縮を選択可能。入力`ABCDEF`、予算6 B。
- RLEでは手入力で組を作る。6文字を正しく表すと6組・12 Bとなり予算超過。復元自体は正しいことも表示する。
- 無圧縮は6 Bで成功。1バイトずつコピーする復元を観察できる。
- 方式変更では再生を停止し、前の送信結果とトレースを破棄する。RLEの下書きは任務内で保持してよいが、別方式の送信や判定に混入させない。
- 失敗文言例：「内容は元に戻りました。ただし12 B必要で、上限を6 B超えています。」
- 実装済み：ホームの任務一覧と任務1クリア後から入れる。RLEの組・未確定入力は方式を切り替えても保持する。任務ごとに下書き・ヒント・クリア状況を分け、再挑戦はその任務の空のRLE入力へ戻す。

## ゲーム任務3：復元機を修理する（旧ミッション4）

- RLE固定。入力`AAAABB`、予算4 B。
- 最初の送信データは意図的に`(4,A)`だけにしたfixture。正常なエンコーダーにバグを入れない。
- 実際に復元すると`AAAA`になり、位置4・5（0始まり）のBが不足する。
- 個数・文字を入力し、末尾に`(2,B)`を補えば4 Bで成功。誤った修理も送って観察できる。
- ヒント：「最後のまとまりの後には、別の文字が来ません。入力終了時にも出力が必要です。」
- 不完全な組列の送信はこの任務だけの特例ではなく、ゲーム共通の試行ルールとする。

## ゲーム任務4：見えない1バイト（旧ミッション5）

- RLEと無圧縮を選択可能。入力`AAAAAABBBBCC`、予算7 B。
- RLEでは自分で組を作る。最良結果は本体6 B、方式情報1 B、合計7 Bで成功。
- 無圧縮は本体12 B、方式情報1 B、合計13 Bで失敗。
- 送信時に方式バイトを実際に付け、受信側はそれを読んで方式を決定する。
- 「合計は6 B？7 B？」の予想操作は任意。誤答で進行不能や減点にはしない。
- この1バイトはゲーム独自形式であり、ZIPの仕様ではないと短く表示する。

## 地球からの依頼と応答

開始時の短い依頼と、実際の判定結果に合った応答で目的を伝える。長い会話送りは不要。

| 場面 | 依頼の例 | 成功時の応答の例 |
| --- | --- | --- |
| チュートリアル | 最初の観測データを8 B以内で地球へ届けよう。 | 観測データを元どおり受信。通信回線の確認完了！ |
| ゲーム任務1 | 次の観測データは6 Bまで。個数と文字でカプセルを作ろう。 | 全10 Bを復元。編隊の情報が届きました！ |
| ゲーム任務2 | 今回の信号には連続がない。6 B以内で送れる方法を選ぼう。 | 全6 Bを受信。今回のデータに合った方法でした！ |
| ゲーム任務3 | 受信データの末尾が不足。欠けた組を補って再送しよう。 | 末尾のBを2個確認。全データがそろいました！ |
| ゲーム任務4 | 今回は読み方も送ろう。方式情報を含めて7 B以内に収めよう。 | 方式情報を読み取り、全12 Bを復元しました！ |

観測データは物語上の設定であり、A～Zに未定義の科学的な意味を付けない。失敗時も内容と容量を分けて伝え、容量超過の送信は試験通信と表示する。

## サイドバー：任務・ヒント・豆知識

1. **今回の任務**：通信上限、現在のサイズ、元どおりに届けるという成功条件を常時表示する。
2. **困ったときのヒント**：押すと段階的に開示する。ゲーム任務1なら「同じ文字が続く部分を探そう」→「個数と文字で1組2 B」→「先頭のAは4個なので(4,A)」の順。最初から正解一覧を並べない。利用しても減点しない。
3. **通信士の豆知識**：方式の名前、使われる場面、歴史などを短い開閉式の記事として置く。クリア後に「今回使った技術」として紹介してもよい。

ヒント・豆知識を開くと再生を停止し、閉じてもステップと入力内容を保つ。狭い画面では補足を下へ移す。歴史の年号・人物・起源や具体的な用途は、記事を実装する際に一次資料で確認し、出典を添える。未確認の史実を埋めない。実装済みの共通解説には、RLEの仕組み・最初に学ぶ理由・技術の位置づけ・可逆圧縮に関係する年表を掲載する。ホームとチュートリアルからも同じ解説を読める。内容と出典は[07](07_compression_guide.md)を参照。

## 成功・失敗の扱い

- 判定は`復元データが完全一致 && 送信サイズ <= 予算`。正解の組列との文字列一致だけで判定しない。
- 結果には「復元：一致／不一致」と「容量：予算内／超過」を独立表示する。
- 形式エラー・復元上限超過では成功にせず、位置と理由を示す。
- ゲーム成功は「ミッションクリア / STAGE CLEAR」、失敗は「再送しよう / RETRY」。元データ・作業結果を勝手に消さない。
- チュートリアル完了とゲーム任務のクリアは別々に保持する。星やランキングは不要。
- ゲーム任務一覧から実装済み任務を選べる。初回は任務1へ案内し、クリア後は次の実装済み任務へ誘導する。未実装の次へボタンは置かない。

## 自由実験モード

- 課題に答えるゲームとは別に、元データをA～Zの1～64文字で入力できる。
- 空入力・対象外文字は説明を出し、処理開始を無効にする。
- サンプル：`AAAAAAAA`、`ABCDEF`、`ABCABCABC`、`AAAAAABBBBCC`。
- RLE／無圧縮、方式情報あり／なしを切り替え、自動圧縮と復元のステップを観察する。
- 任意予算はMVPでは不要。小さくならない結果も正しく表示する。

## 用語カード

いつでも開ける「バイト」「可逆圧縮」「RLE」「復元」「アーカイブと展開」を用意する。開くと再生を停止し、閉じても入力内容と再生位置を失わない。

## RLE章から次の章への接続（合意済み・未実装）

現在のチュートリアルとゲーム任務1～4を「RLE章」と位置付ける。既存の任務番号・入力・予算は維持する。任務3は不足を修理して正しく復元すること、任務4は読み方を伝える情報にも容量が必要なことを扱い、後続の方式とファイル形式へつなぐ。

RLE章の振り返りで、次の通信データ例として`ABCABCABC`を提示する。1文字の連続はないが、同じ並びが繰り返されることをプレイヤーに見つけてもらう。

> 同じ文字を数えるだけでは足りない。前に送った並びを使い回せないだろうか？

次のLZ77章では、文字をそのまま送るか、すでに出た並びを参照するかを自分で選ぶ任務へ進む。手入力による試行・復元・修正の流れを引き継ぐ。参照の記録形式と通信予算を定めるまでは、`ABCABCABC`が必ず小さくなるとは表示しない。

以降はハフマン、組み合わせ、ZIPの順。章の入口に「今回の困りごと」と「獲得する工夫」、完了時に「次の工夫が必要になるデータ」を置く。ZIPは到達点として先に紹介できるが、実装済みの任務だけを開始可能にする。後続章の画面番号と具体的な形式は各章の仕様で定める。
