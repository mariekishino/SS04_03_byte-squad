# 画面と実装計画

## 推奨構成

新規開発ではTypeScript＋React＋Viteを基本案とする。既存の同等環境があれば再利用する。コア検証には既存のテスト環境、なければVitest等を使う。依存のバージョンは実装先で整合するものを選ぶ。

ブラウザ内で完結させる。サーバー、DB、LLM、外部アセット取得に依存しない。宇宙船や地球の簡単な装飾はCSSまたはSVGで作れる。画像素材を先に大量生成する必要はない。

描画はDOM＋CSS Grid＋小さなSVGを基本にする。少数の編隊・自機・文字表現なので専用ゲームエンジンやCanvasは必須ではない。ASCII調はビジュアルの指定であり、全画面をターミナル文字列にする要件ではない。詳しくは06を参照する。

## 画面構成

### ミッション選択

等幅文字のタイトル、短い目的説明、STARTボタン、番号付きの5つのSTAGE、自由実験への入り口、用語カード。ミッション選択はアーケードのステージ一覧として描く。クリア済み表示はセッション内で保持すればよい。永続化は必須ではない。

開始画面には「文字データを小さく送り、地球で元に戻す5つの通信ミッション」と案内し、「今回は圧縮・復元の基礎を体験します。実ファイルの保存やZIPの展開は今後の学習範囲です」と短く補足する。

全5問をクリアしたら「表現を変えても元に戻せる」「圧縮で大きくなる場合もある」「方式情報にも容量が必要」という振り返りと、自由実験への入口を表示する。実ファイルの保存・読み込みやZIPの展開は今後の学習として紹介し、未実装機能を開始できるボタンは置かない。

### ミッション画面

メインは一つの2Dプレイフィールドとする。最上部のHUDにSTAGE・目的・送信サイズ・通信上限を置く。次の3つの役割をフィールドの上から下へ配置する。

| 領域 | 表示・操作 |
| --- | --- |
| 上部：データ編隊／受信編隊 | 元データの1バイト＝1機。復元中は受信編隊を主表示し、元データは比較用の別レイヤーとしてラベル付きで参照可能にする |
| 中央：符号化カプセルと通信レーン | 個数・値の2マスの組、選択範囲、復元元の組。RLE／無圧縮切替と手動編集は対応する操作パネルへ置く |
| 下部：自機とコマンド | 照準選択、符号化、送信、ステップ操作。処理中の現在値・個数を表示する |

フィールド直下に操作キーの凡例と現在の処理を説明する1文を置く。PCでは補足パネルを右に配置してよいが、ゲーム画面を主役にする。狭い画面では補足を下へ移し、主要操作をタッチボタンにする。長い編隊は左から右、上から下へ折り返し、論理インデックスで元の順番を維持する。

サイズ欄は「元データ」「本体」「方式情報」「送信合計」「上限」を表示する。方式情報なしの場合も0 Bと取り決めを示す。

### 結果

「復元：一致／不一致」「容量：予算内／超過」を独立表示する。不一致は不足や余分なバイトも可視化する。成功なら次へ、失敗なら編集へ戻る。元データや作業結果を勝手に消さない。

成功はSTAGE CLEARと短い受信確認の演出、失敗はRETRYと理由をフィールド内に表示する。詳細は日本語を併記する。

## 操作とアクセシビリティ

- 再生速度は初期1ステップ／秒。次へ／前へは常に手動で使える。
- 自動再生中の次へ／前へは一時停止して1ステップ動く。
- 最初の前へ、最後の次へは無効。完了時はタイマーを止める。
- 「圧縮」「復元」のどちらを再生中か見出しに表示する。
- ドラッグ専用にしない。ネイティブbutton・select・inputを基本とし、キーボードで操作できるようにする。
- 色だけに意味を持たせず、ラベル・枠・アイコンを併用する。
- フォーカスを視認できるようにする。通常文字のコントラストを十分確保する。
- reduced-motion設定では移動演出を抑える。演出を止めても学べる状態表示を残す。
- サウンドはMVPでは不要。宇宙の装飾よりデータの可読性を優先する。
- バイトの数値・ビット表示は補助パネルに隠し、通常の流れを煩雑にしない。
- 06のキー操作を実装する。入力欄や通常のボタンにフォーカスがある場合はゲーム用ショートカットで標準操作を奪わない。
- レトロ演出の走査線は任意の薄い装飾に留める。点滅・画面揺れ・強いぼかしで文字を読みにくくしない。

## 状態設計

アプリのフェーズは `editing → encoding-review → decoding-review → result` を基本にする。ミッション1はencoding-reviewから開始できる。ミッション4は編集済みfixtureを送信できる。

推奨する状態の分離：

- ミッション定義：ID、入力、予算、方式情報の有無、許可する方式、操作タイプ。
- 作業状態：選択方式、手動の組、修理用の組。
- 計算結果：本体、パケット、復元結果、比較結果、各トレース。
- 再生状態：対象フェーズ、ステップ番号、再生中か。
- 進行状態：選択ミッション、クリアしたID。

サイズや成功可否は結果から導出し、手入力の状態として重複保持しない。ミッション変更、入力変更、方式変更、リセット、アンマウント時にタイマーを確実に止める。

## 推奨モジュール分割

| ファイル例 | 責務 |
| --- | --- |
| `src/core/rle.ts` | 圧縮・復元とそのイベント生成 |
| `src/core/packet.ts` | 方式バイトの付加・解釈、無圧縮処理 |
| `src/core/metrics.ts` | 容量計算とバイト比較 |
| `src/game/missions.ts` | 5問のデータと修理fixture |
| `src/game/state.ts` | フェーズ遷移と操作状態 |
| `src/components/ByteStrip.tsx` | 値・位置・強調の共通表示 |
| `src/components/RunEditor.tsx` | 組の作成、取消、修理 |
| `src/components/PlaybackControls.tsx` | ステップ再生 |
| `src/components/SizePanel.tsx` | サイズと予算 |
| `src/components/ComparisonPanel.tsx` | 復元と元データの比較 |
| `src/components/ArcadeField.tsx` | 編隊・通信レーン・自機の配置と現在状態の描画 |
| `src/components/ArcadeHUD.tsx` | STAGE・現在の容量・予算・操作モード |

これは責務の例であり、同等の分割でよい。コアはDOMやReactへ依存させない。

## 実装順序

1. **コアを確定する**：RLE、無圧縮、パケット、容量、比較を実装し、03・05の例を検証する。
2. **1問を縦に完成させる**：ミッション1を圧縮から受信・判定まで操作可能にする。
3. **手動操作と失敗を作る**：ミッション2～4を実装する。正解だけでなく、予算超過・不足の表示も作る。
4. **形式情報を導入する**：ミッション5と自由実験、用語カードを完成させる。
5. **操作と画面を整える**：キーボード、狭い画面、タイマー、演出を確認する。
6. **受け入れ確認と引き渡し**：05を検証し、プロジェクト側READMEに起動手順と制約を書く。

各段階で、実際のデータ処理と画面がつながっている状態を保つ。公開・ホスティングは実装完了とは別であり、実行先の指示とユーザーの依頼に従う。
