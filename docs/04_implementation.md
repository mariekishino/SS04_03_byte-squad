# 画面と実装計画

## 推奨構成

新規開発ではTypeScript＋React＋Viteを基本案とする。既存の同等環境があれば再利用する。コア検証には既存のテスト環境、なければVitest等を使う。依存のバージョンは実装先で整合するものを選ぶ。

ブラウザ内で完結させる。サーバー、DB、LLM、外部アセット取得に依存しない。宇宙船や地球の簡単な装飾はCSSまたはSVGで作れる。画像素材を先に大量生成する必要はない。

描画はDOM＋CSS Grid＋小さなSVGを基本にする。少数の編隊・自機・文字表現なので専用ゲームエンジンやCanvasは必須ではない。ASCII調はビジュアルの指定であり、全画面をターミナル文字列にする要件ではない。詳しくは06を参照する。

## 画面構成

### ホーム：説明とモード選択

ページを開いたら、02の「宇宙の発見を、地球へ届けよう。」の文章と成功条件を最初に表示する。ゲームの目的を理解してから選べるよう、説明の下に次の入口を置く。

- 「チュートリアル：通信の練習」＋「ガイドと一緒に、圧縮と復元の仕組みを体験しよう。」
- 「ゲーム：通信任務に挑戦」＋「自分でデータをまとめ、限られた容量で地球へ届けよう。」

曖昧なSTARTボタン1つにまとめない。チュートリアルを未完了でもゲームへ進める。初回表示で任務や自動再生を開始せず、操作の選択を待つ。自由実験は補助入口、未実装機能は準備中の説明にする。

現在の画面をチュートリアルへ移し、チュートリアル完了とゲームのクリア件数を別々に表示する。ゲーム任務一覧は番号1～4で表示し、旧IDとの対応は02に従う。進捗はセッション内で保持すればよく、永続化は必須ではない。

チュートリアル完了後は「通信任務に挑戦」を案内する。ゲーム4任務の完了後は「表現を変えても元に戻せる」「圧縮で大きくなる場合もある」「方式情報にも容量が必要」を振り返り、自由実験へ進めるようにする。実ファイル保存やZIP展開は今後の学習として紹介する。

### チュートリアル／ゲームの画面

メインは一つの2Dプレイフィールドとする。最上部のHUDにTUTORIALまたはゲーム任務番号・目的・送信サイズ・通信上限を置く。次の3つの役割をフィールドの上から下へ配置する。

| 領域 | 表示・操作 |
| --- | --- |
| 上部：データ編隊／受信編隊 | 元データの1バイト＝1機。復元中は受信編隊を主表示し、元データは比較用の別レイヤーとしてラベル付きで参照可能にする |
| 中央：符号化カプセルと通信レーン | 個数・値の2マスの組、選択範囲、復元元の組。RLE／無圧縮切替と手動編集は対応する操作パネルへ置く |
| 下部：自機とコマンド | チュートリアルはステップ操作、ゲームは個数・文字の入力と組の追加・編集・取消・送信。処理中の現在値・個数を表示する |

フィールド直下に操作キーの凡例と現在の処理を説明する1文を置く。PCでは補足パネルを右に配置してよいが、ゲーム画面を主役にする。狭い画面では補足を下へ移し、主要操作をタッチボタンにする。長い編隊は左から右、上から下へ折り返し、論理インデックスで元の順番を維持する。

ゲームのRLE編集欄はラベル付きの個数入力と文字入力、＋／−、文字選択を用意し、フォームの標準操作を使えるようにする。課題の元データは編集させない。入力値の形式エラーと、復元後の内容不一致は別々に扱う。編集した内容を入力時に正解へ補正しない。

サイズ欄は「元データ」「本体」「方式情報」「送信合計」「上限」を表示する。方式情報なしの場合も0 Bと取り決めを示す。

### サイドバー

「今回の任務（上限と成功条件）」「困ったときのヒント」「通信士の豆知識」の順で配置する。ゲームのヒントは02に従い段階的に開示し、初期状態で答えを並べない。豆知識は方式名・用途・歴史を短く紹介する開閉式の記事とし、歴史や具体的な用途の記事には確認した出典を付ける。閲覧にネットワーク通信を必須とせず、本文はアプリに含める。

ヒント・豆知識・用語カードを開く操作と同時に再生を停止し、入力内容と再生位置は保つ。ヒントの利用段階は任務ごとに保持し、別の任務のヒントが混入しないようにする。

### 結果

「復元：一致／不一致」「容量：予算内／超過」を独立表示する。不一致は不足や余分なバイトも可視化する。ゲームでは成功なら次の実装済み任務へ、失敗なら組の編集へ戻る。元データや作業結果を勝手に消さない。

ゲーム成功はSTAGE CLEARと短い受信確認の演出、失敗はRETRYと理由をフィールド内に表示する。チュートリアル完了はTRAINING COMPLETEとし、ゲームのクリアとして数えない。詳細は日本語を併記する。

## 操作とアクセシビリティ

- 観察中の再生速度は初期1ステップ／秒。次へ／前へは手動でも使える。
- 自動再生中の次へ／前へは一時停止して1ステップ動く。
- 最初の前へ、最後の次へは無効。完了時はタイマーを止める。
- 「圧縮」「復元」のどちらを再生中か見出しに表示する。ゲームの入力中は「カプセルを作る」と表示し、観察用の再生ボタンを主操作にしない。
- ゲームの送信後は復元を自動再生し、一時停止・前後移動・「結果を見る」で末尾への移動を可能にする。自動圧縮の再生を送信条件にしない。
- ドラッグ専用にしない。ネイティブbutton・select・inputを基本とし、キーボードで操作できるようにする。
- 色だけに意味を持たせず、ラベル・枠・アイコンを併用する。
- フォーカスを視認できるようにする。通常文字のコントラストを十分確保する。
- reduced-motion設定では移動演出を抑える。演出を止めても学べる状態表示を残す。
- サウンドはMVPでは不要。宇宙の装飾よりデータの可読性を優先する。
- バイトの数値・ビット表示は補助パネルに隠し、通常の流れを煩雑にしない。
- 06のキー操作を実装する。入力欄や通常のボタンにフォーカスがある場合はゲーム用ショートカットで標準操作を奪わない。
- レトロ演出の走査線は任意の薄い装飾に留める。点滅・画面揺れ・強いぼかしで文字を読みにくくしない。

## 状態設計

入口の状態は`home / tutorial / game / experiment`として区別する。処理フェーズは次のように分ける。

- チュートリアル：`encoding-review → decoding-review → result`。
- ゲーム：`editing → decoding-review → result → editing`。送信時に手動の本体を確定する。無圧縮の場合は元データのコピーを本体にする。
- 自由実験：`editing → encoding-review → decoding-review → result`。

推奨する状態の分離：

- 教材定義：内部ID、モード、画面の任務番号、入力、予算、方式情報の有無、許可する方式、操作タイプ。
- 作業状態：方式、未確定の個数・文字、確定済みの組列、修理fixture、編集対象。
- 計算結果：送信時の本体コピー、パケット、復元結果、比較結果、実際の変換トレース。
- 再生状態：対象フェーズ、ステップ番号、再生中か、旧タイマーを除外する世代。
- 補足状態：ヒントの開示段階、開いている用語・豆知識。
- 進行状態：チュートリアル完了、ゲームのクリアしたID、選択中の任務。

サイズや成功可否は結果から導出し、重複保持しない。モード変更、任務変更、入力変更、方式変更、リセット、アンマウント時にタイマーを止める。失敗後に編集へ戻るときは組を保ち、編集を開始したら旧結果・トレースを破棄する。別モードへ移るときは入力を混ぜない。チュートリアルを開いたことがゲーム進捗や下書きを変更しないようにする。

## 実装順序と現在の進捗

コアに加え、以下の1～3は実装・検証済み。今回の範囲についてキーボード・タッチ・狭い画面・モード分離を検証し、READMEへ手順と制約を記載した。4のうち任務2（RLEと無圧縮の選択）と任務3（欠損した末尾の修理）も実装済み。次は任務4を進め、MVP全体が揃った後に6の受け入れ確認を行う。

1. **入口とチュートリアルを分ける**：02の説明文と2つの入口を作る。既存画面をチュートリアルと明示し、完了表示と進捗をゲームから分ける。
2. **最初の通信任務を完成させる**：ゲーム任務1（旧ミッション2）を個数・文字の手入力から送信・復元・修正まで作る。チュートリアル未完了でも挑戦できるようにする。
3. **自分で解く体験を確認する**：任務条件、段階的なヒント、RLEの豆知識を加え、合法な誤答・不足・容量超過を試して直せることを確認する。ここを次の実装の一区切りとしてユーザーに報告する。
4. **残りのゲーム任務を追加する**：任務2～4で無圧縮の選択、修理、方式情報を導入する。歴史などの豆知識を追加する場合は出典を確認する。
5. **自由実験と用語を整える**：元データの入力による比較と、圧縮・復元・展開の区別を補う。
6. **受け入れ確認と引き渡し**：05に従い、キーボード・タッチ、狭い画面、再生停止、モード分離を検証し、READMEへ実装済み範囲と手順を記載する。

各段階で、実際のデータ処理と画面がつながっている状態を保つ。公開・ホスティングは実装完了とは別であり、実行先の指示とユーザーの依頼に従う。

## MVP完了後の順序

05の合意済みロードマップに従い、LZ77の考え方、ハフマン、組み合わせ、実ファイルとZIPの順に進める。実ファイル保存を別方式の学習より先に作る旧計画は、この順序に置き換える。

次の実装はRLE章の任務4「見えない1バイト」。その後、自由実験・用語、MVPの受け入れ確認を経て、次の圧縮方式としてLZ77章へ進む。各章の開始時に教材・記録形式・容量計算・復元規則・完成条件を具体化し、一章ずつ操作できる状態まで完成させる。
